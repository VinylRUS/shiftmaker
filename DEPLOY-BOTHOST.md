# Деплой ShiftMaker на bothost.ru (тариф Pro)

Пошаговая инструкция. Всё, что нужно для деплоя, уже лежит в репозитории:
`Dockerfile`, `.dockerignore`, `scripts/init-db.mjs`, эндпоинт `/health`.

Репозиторий: **https://github.com/VinylRUS/shiftmaker**

---

## Как это устроено (важно понимать)

1. **Bothost собирает Docker-образ из вашего Git-репозитория** при каждом пуше
   и запускает его в контейнере. Сборка идёт по нашему `Dockerfile`.
2. **Особенность платформы:** на части нод каталог `/app` контейнера при старте
   монтируется с исходниками из Git — артефакты сборки (`.next/`) в нём
   **недоступны**. Поэтому наш `Dockerfile` держит приложение в `/usr/src/app`,
   а не в `/app` (рекомендация из документации Bothost).
3. **База данных SQLite живёт в `/app/data/schedule.db`** — это постоянный том:
   данные переживают деплои, рестарты и обновления кода. На Pro-тарифе
   доступны автоматические бэкапы.
4. **Приложение слушает `0.0.0.0` и порт из переменной `PORT`** — ровно то,
   что требует Bothost. Порт в панели должен совпадать с ним (по умолчанию 3000).
5. При первом старте (когда базы ещё нет) скрипт `scripts/init-db.mjs` создаёт
   таблицы и заливает демо-данные — приложение сразу открывается «живым».
   Демо-сотрудников потом можно удалить в панели «Сотрудники».

## Шаг 1. Залейте код на GitHub

Репозиторий уже создан: **https://github.com/VinylRUS/shiftmaker** — код в нём
(ветка `main`). Если вы клонировали его заново, обновления отправляются так:

```bash
cd shiftmaker
git add -A
git commit -m "описание изменений"
git push origin main
```

Если не хотите возиться с Git — есть вариант «из архива» (Приложение Б в конце),
но тогда не будет автообновления при пуше.

## Шаг 2. Создайте приложение на Bothost

1. На дашборде bothost.ru нажмите **«Создать бота»**.
2. Выберите тип **GitHub** и вставьте ссылку на репозиторий, ветка **main**.
   - Приватный репозиторий тоже подходит: Bothost умеет подключаться через
     токен/SSH deploy key (спросит при подключении).
3. Раскройте **«Дополнительные настройки»**:
   - ✅ **«Использовать собственный Dockerfile»** — обязательно, иначе платформа
     сгенерирует свой образ и приложение упадёт на старте.
   - Поле «Главный файл» при этом не важно — реальная команда запуска задаётся
     нашим `Dockerfile`. Можно указать `scripts/init-db.mjs`.
4. Если форма попросит токен Telegram-бота — приложение его не использует.
   Можно создать любого «технического» бота у @BotFather и вставить его токен
   просто чтобы пройти форму, либо оставить поле пустым, если платформа
   позволяет.

## Шаг 3. Включите домен и порт

1. В настройках приложения включите **«Использовать домен»**.
2. Тип домена:
   - **Поддомен `*.bothost.tech`** — выдаётся автоматически, HTTPS уже настроен;
   - либо **свой домен**: A-запись в DNS на IP, который выдаст поддержка.
3. **Внутренний порт: `3000`** — он должен совпадать с `PORT` приложения
   (по умолчанию 3000, как в `Dockerfile`).
4. Сохраните и нажмите **«Деплой»** / «Передеплоить».

> После любой смены порта или домена нужен повторный деплой.

## Шаг 4. Дождитесь сборки

В **логах сборки** должно пройти примерно так (3–6 минут на Pro):

```
npm ci                → зависимости
npx prisma generate   → Prisma-клиент
npm run build         → сборка Next.js
Build completed
```

Затем в **логах работы**:

```
[init-db] DATABASE_URL=file:/app/data/schedule.db -> /app/data/schedule.db (новая база)
🚀 Your database is now in sync with your Prisma schema.
[init-db] Демо-данные: 5 сотрудников, 22 смен (неделя с …)
✓ Ready in …
```

## Шаг 5. Проверьте

| URL                                          | Что должно быть                          |
|----------------------------------------------|------------------------------------------|
| `https://ваш-домен/health`                   | `{"ok":true,"db":"up","employees":5,…}`  |
| `https://ваш-домен/`                         | Таблица «График смен» с демо-данными     |
| `https://ваш-домен/?mode=view`               | Режим только чтение (ссылка сотрудникам) |

Ссылка для сотрудников (без права редактирования):

```
https://ваш-домен.bothost.tech/?mode=view
```

## Обновления

- `git push` → Bothost автоматически пересобирает образ и перезапускает
  приложение. Данные в `/app/data` сохраняются.
- Расписание не «слетает»: база и код живут раздельно.

## Переменные окружения (по желанию, в панели Bothost)

| Переменная    | По умолчанию | Действие                                            |
|---------------|--------------|-----------------------------------------------------|
| `SEED_DEMO`   | `1`          | `0` — не заливать демо-данные при первом старте     |
| `DATABASE_URL`| задан в образе | `file:/app/data/schedule.db` — менять не нужно   |
| `PORT`        | задаёт платформа | должен совпадать с портом в панели             |

## Бэкапы

- **Pro-тариф:** автоматические бэкапы включены.
- Вручную: файловый менеджер на карточке приложения → скачать
  `/app/data/schedule.db`. Это и есть вся база — один файл.
- Можно поднять копию локально: положить файл в `db/custom.db` и запустить
  `npm run dev`.

## Типичные проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| **502/504 на домене** | Порт в панели ≠ порт приложения | Поставить порт 3000 в панели; проверить `https://домен/health`; после смены — передеплоить |
| **`MODULE_NOT_FOUND` вида `/app/…`** | Приложение собрано не нашим Dockerfile | Убедиться, что включена галка «Использовать собственный Dockerfile», передеплоить |
| Статус **restarting** | Процесс падает на старте | Открыть **логи работы** (не сборки), найти первую ошибку; обычно она текстом видна |
| Сборка падает, **код 137 / Killed** | Не хватило памяти при сборке | Запустить деплой повторно; если повторяется — тикет в поддержку (Pro: 2 ГБ) |
| **Данные пропали** | База не в томе | У нас `DATABASE_URL=file:/app/data/schedule.db`; проверить, что в панели не переопределена другая переменная |
| Пустая таблица после первого деплоя | `SEED_DEMO=0` | Так и задумано: добавьте сотрудников в панели «Сотрудники» |
| `prisma` ругается при старте | Конфликт схемы и базы | Логи работы покажут текст; пишите в поддержку/мне |

## Приложение А. Что именно делает наш Dockerfile

```dockerfile
FROM node:22-bookworm-slim        # Debian + openssl для Prisma
WORKDIR /usr/src/app              # НЕ /app: артефакты сборки переживут bind mount
COPY package.json package-lock.json ./
RUN npm ci                        # воспроизводимая установка зависимостей
COPY prisma ./prisma
RUN npx prisma generate           # клиент + движок под эту платформу
COPY . .                          # исходники (по .dockerignore без мусора)
RUN npm run build                 # next build
RUN mkdir -p /app/data && chmod 777 /app/data   # том для SQLite
ENV DATABASE_URL=file:/app/data/schedule.db NODE_ENV=production
EXPOSE 3000
CMD ["sh", "-c", "node scripts/init-db.mjs && npm start"]
```

`npm start` = `next start -H 0.0.0.0 -p ${PORT:-3000}` — порт берётся из
переменной `PORT`, которую передаёт Bothost.

## Приложение Б. Деплой из архива (без Git)

1. Возьмите файл `shiftmaker-bothost.zip` (без `node_modules`, ~1 МБ).
2. В [профиле](https://bothost.ru/profile.php) включите «Загрузка бота из архива».
3. На дашборде появится кнопка **«Загрузить из архива»** → мастер из 3 шагов:
   архив → настройки (язык Node.js, главный файл `scripts/init-db.mjs`) → деплой.
4. Домен и порт — как в шагах 3–4 выше.
5. Обновление — кнопкой «залить новый архив» на карточке приложения;
   домен, порт, переменные и данные в `/app/data` сохраняются.

Минус по сравнению с Git: нет автообновления при пуше — каждый раз нужно
грузить новый архив руками.
